# 03. 디자인 시스템·다국어·테마·접근성

연결: [메인](../AGENTS.md), [화면](02-information-architecture-journeys.md), [검증](09-quality-deployment-mobile-release.md)

## 1. 디자인 원칙

중국어 고객 예약 화면과 한국어 호텔·기사·운영자 화면에 같은 로고·타이포·색·버튼·알림·폼을 사용한다. 실제 예약 화면에는 장식보다 가격·시간·인계 장소의 식별성을 우선한다. 중국어 간체를 고객 기본 언어로 제공한다.

초기 방향은 제주 바다를 연상시키는 teal 계열과 밝은 중성 배경, 핵심 행동에만 사용하는 따뜻한 강조색이다. 아래 색은 시작값이며 모든 텍스트 조합은 실제 대비 검사 후 확정한다.

| 토큰 | 라이트 시작값 | 다크 시작값 | 용도 |
|---|---|---|---|
| `--background` | `#F8FAFC` | `#0B1220` | 기본 배경 |
| `--surface` | `#FFFFFF` | `#111C2E` | 카드·패널 |
| `--text-primary` | `#0F172A` | `#F1F5F9` | 본문 |
| `--text-muted` | `#475569` | `#CBD5E1` | 보조 정보 |
| `--brand` | `#0F766E` | `#5EEAD4` | 브랜드·링크 |
| `--action-bg` | `#0F766E` | `#5EEAD4` | 주요 버튼 |
| `--action-text` | `#FFFFFF` | `#042F2E` | 주요 버튼 글자 |
| `--border` | `#CBD5E1` | `#475569` | 입력·구분 |
| `--danger` | `#B91C1C` | `#FCA5A5` | 오류 |

색 이름을 개별 컴포넌트에 직접 넣지 않고 의미 토큰을 사용한다. 배송 상태는 색·아이콘·텍스트를 함께 사용한다. 사진 위 텍스트는 배경 처리 없이 배치하지 않는다.

## 2. 레이아웃·컴포넌트

**모바일 우선이 기본이다.** 고객·기사·호텔 화면은 360–430px 세로 모바일 화면을 기준으로 먼저 설계·구현·검수하고, 태블릿·데스크톱은 그 레이아웃을 넓히는 확장으로 다룬다. 고객은 위챗 내장 브라우저, 기사·호텔은 설치형 PWA가 주 사용 환경이다. 데스크톱을 기준으로 먼저 만든 뒤 줄이는 방식은 쓰지 않는다. 운영자 `/admin`만 데스크톱 작업을 주로 하되, 긴급 확인·배차 조정은 모바일에서도 가능해야 한다. 스타일은 모바일 기본값에 `min-width` 미디어 쿼리로 확장한다.

- 기본 글자 16px, 본문 행간 약 1.5 이상에서 시작해 언어별 조정.
- 모바일 주요 터치 영역은 44×44 CSS px 이상을 제품 목표로 한다.
- 예약 폼은 모바일 한 열, 데스크톱 입력·요약 두 열. 요약의 고정 위치가 화면을 가리지 않게 한다.
- 모바일 하단 예약 버튼은 safe-area를 반영하며 키보드가 열리면 입력 영역을 가리지 않는다.
- 상태가 복잡한 표는 모바일 카드·요약으로 전환한다. 운영자 대량 처리 표는 가로 스크롤 범위를 명확히 한정한다.
- 키보드 사용 시 focus ring을 제거하지 않는다. 모달 종료 후 열었던 버튼으로 초점을 복귀한다.

공통 컴포넌트 계약:

| 컴포넌트 | 필수 입력 | 주요 상태 |
|---|---|---|
| `RouteCard` | 출발·도착 유형·번역 제목·활성 상태 | available / unavailable |
| `HotelPicker` | 언어·검색어·권역·선택 지점 ID | 검색 중·동명 지점·결과 없음 |
| `SlotPicker` | 날짜·시간대·가능 용량 | 선택·마감·불가 사유 |
| `PriceSummary` | 서버 견적·통화·만료 시각 | 유효·갱신 중·만료 |
| `PolicyConsent` | 문서 ID·버전·필수 여부 | 동의·변경되어 재동의 필요 |
| `BagTimeline` | 이벤트·발생 시각·마지막 갱신 | 진행·부분 완료·지연 |
| `HandoffCard` | 고객 언어·한국어·장소·시간 | 온라인·오프라인 사본 |
| `ThemeToggle` | 현재 선택·해석된 테마 | light / dark + system 설정 |
| `LocaleSwitcher` | 현재 경로·지원 언어 | 선택·미번역 알림 |
| `IntegrationStatus` | mock/sandbox/live·검증 상태 | 운영자·개발환경에서 표시 |

## 3. 테마 토글의 실제 동작

1. 헤더 또는 계정 메뉴에서 라이트/다크를 직접 바꿀 수 있는 토글 제공.
2. 설정 화면에서 ‘기기 설정 따르기’를 별도로 선택할 수 있게 한다.
3. 저장값은 `light | dark | system`, 실제 렌더값은 light 또는 dark.
4. 비회원은 쿠키·로컬 설정, 회원은 프로필 선호를 저장한다. 로그인 시 현재 기기 선택을 우선하고 필요할 때 계정 기본값으로 동기화한다.
5. 서버는 읽을 수 있는 선호를 반영한다. system의 최초 테마는 최소 초기 스크립트와 CSS로 정해 깜박임을 줄인다. hydration 경고를 단순 숨기기만 해서 해결한 것으로 보지 않는다.
6. 운영체제 테마 변경은 system 모드에서만 반영한다.
7. 토글에는 접근 가능한 이름과 현재 상태를 제공한다. 아이콘만으로 의미를 전달하지 않는다.

지도·PG 결제창처럼 외부 서비스가 테마 제어를 제공하지 않으면 주변 UI만 일관되게 처리한다. 외부 결제창까지 테마가 적용된다고 약속하지 않는다. QR·바코드는 스캔 안정성을 위해 밝은 단색 배경과 여백을 유지한다.

## 4. 다국어 데이터 구조

코드 문자열은 `packages/i18n`에서 의미 기반 키로 관리한다. 예: `booking.pickupDeadline`, `payment.pendingVerification`, `handoff.readyForPickup`. 문장을 조각내어 연결하지 않고 변수·복수형·날짜·금액을 메시지 형식으로 처리한다.

운영 콘텐츠는 콘텐츠 ID와 locale별 번역 행을 가진다. 게시 상태는 언어별로 관리한다. 고객용 핵심 안내는 중국어 간체 승인본을 먼저 준비하고, 한국어 원문을 수정했다고 중국어 번역을 자동 게시하지 않는다.

| 정보 | 처리 규칙 |
|---|---|
| 일반 설명·가이드 | 요청 언어 → 승인된 대체 언어, 대체 표시 |
| 가격·취소·보험·금지 품목·필수 동의 | 해당 언어 승인본 없으면 그 언어의 결제 진입을 차단하거나 지원 흐름 제공 |
| 호텔명·주소 | 한국어 원명 유지 + 고객 언어 별칭, 지점 식별자 공통 |
| 브랜드명 | 언어별 표시명 허용, 동일 브랜드 ID |
| 고객 문의·기사 메모 | 원문을 보존하고 번역본이 있으면 출처·검수 상태를 구분 |
| 법적 동의 | 언어·버전·동의 시각·주문 ID 보존 |

번역 워크플로: draft → review → published → archived. 원문 수정 시 관련 번역을 `needs_review`로 표시한다. 예약 당시 약관 스냅샷은 이후 번역 변경으로 덮어쓰지 않는다.

## 5. 날짜·통화·연락처

- DB 이벤트 시각은 `timestamptz`, 서비스 날짜는 한국 기준 date, 운영 슬롯은 해당 시간대의 절대 시각으로 변환한다.
- 고객 기기가 중국 시간이어도 ‘수거 오전 10시’는 한국 시간 10시로 표시한다. 예약 확인에 한국 시간 라벨을 둔다.
- 금액은 `amount_minor + currency` 구조. KRW는 원 단위 정수, 다른 통화는 해당 최소 단위.
- 외화 환산은 참고 금액·기준 시각을 표시한다. PG의 실제 청구 통화와 혼동시키지 않는다.
- 전화번호 국가코드 선택, 국제 형식 정규화, 한국 번호 강제 금지. 이메일·위챗 등 연락 채널은 어댑터 지원 여부에 맞춰 표시한다.
- 이름은 한글·중국어·라틴문자·공백·하이픈 등을 허용하고 필요 이상으로 영문 성/이름을 강제하지 않는다.

## 6. 검색·SEO·공유

공개 콘텐츠에 locale별 title·description·canonical·hreflang·공유 이미지와 대체 텍스트를 제공한다. 중국어 호텔 별칭과 수하물 서비스 검색어를 실제 본문에 자연스럽게 반영한다. 주문·기사·호텔·관리자·결제 페이지는 검색 색인 대상에서 제외하고 인증으로 보호한다. robots 설정을 보안 대체로 사용하지 않는다.

개인화되지 않은 콘텐츠만 캐시한다. 회원 이름·주문 요약을 공개 CDN 캐시에 저장하지 않는다. 폰트는 라이선스를 확인한 파일을 자체 제공하고 한·중·영 문자 로딩 비용을 줄인다. 차단 가능성이 있는 외부 폰트·분석 스크립트가 없어도 핵심 예약이 동작해야 한다.

## 7. 접근성·현장 사용성

- WCAG 2.2 AA를 제품 검증 목표로 두되 실제 평가 없이 준수 인증을 표방하지 않는다.
- 오류는 필드와 연결하고 페이지 상단 요약에서 해당 필드로 이동 가능하게 한다.
- 결제 처리 중 상태는 적절한 라이브 영역으로 알리되 매초 읽지 않는다.
- 드래그만 가능한 동작에 버튼 대안을 제공한다.
- 모션 축소 설정을 존중하고 예약 완료를 애니메이션 시청에 의존시키지 않는다.
- 기사 화면은 장갑·한 손·햇빛 상황을 고려해 큰 버튼과 짧은 문장을 사용한다.
- 호텔 카드·예약증 인쇄에는 다크 배경을 적용하지 않는다.
- 현장 안내 이미지는 이미지 안의 번역 불가능한 글자를 최소화하고 텍스트 설명을 별도 제공한다.

## 9. 근거

이 문서의 토큰·구성·크기는 프로젝트 설계 목표다. 네트워크 의존성 축소의 근거는 [Vercel 중국 접속 안내](https://vercel.com/kb/guide/accessing-vercel-hosted-sites-from-mainland-china), 확인 2026-09-29. 접근성은 구현 시 [W3C WCAG](https://www.w3.org/TR/WCAG22/) 원문과 테스트 도구를 함께 사용한다.
