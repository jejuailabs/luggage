# 01. 중국인 관광객 수하물 플랫폼의 제품·시장·범위

기준일: 2026-09-29 · 연결: [메인](../AGENTS.md), [화면](02-information-architecture-journeys.md)

## 1. 대상과 서비스

중국인 개별관광객 중 렌터카 없이 이동하거나 숙소를 바꾸면서 캐리어 때문에 일정이 제약되는 고객을 우선 대상으로 한다. 국적만으로 렌터카 이용 여부를 단정하지 않는다.

고객에게 제공하는 기능은 **제주 내 수하물 수거·보관·배송·인계**에 한정한다. 판매 노선은 숙소→공항, 공항→숙소, 숙소→숙소다. 개별 노선의 호텔·권역·마감 시간·인계 장소는 운영 설정으로 제한한다. 여객 운송, 항공사 수하물 체크인, 해외 배송은 이 제품의 기능이 아니다.

핵심 상황은 ‘체크아웃 후 출국 전까지 짐 없이 관광’이다. 부차 상황은 ‘도착 후 숙소 체크인 전 관광’과 ‘숙소 이동일에 짐을 들고 다니지 않기’다. 각 상황별로 시간 약속·인계 책임을 명확히 보여준다.

## 2. 확인된 시장·경쟁 관찰

| 관찰 | 제품에 반영할 점 | 해석의 한계 |
|---|---|---|
| 제주관광공사 2025년 조사에서 외국인 관광객의 개별여행 비중 91.9%, 평균 체류 4.79일 | 짧은 여행 중 설치 없이 끝나는 예약 | 중국인만의 수치·짐배송 구매 의향이 아님 |
| Klook 중국어 페이지에서 짐캐리 제주 공항↔숙소·숙소↔숙소 판매 | 중국어 예약·호텔 안내·사진 등록의 기본 수준 확인 | 중국어 서비스가 없는 시장으로 소개하지 않음 |
| 트립백의 제주공항 대면 인계 안내 | 출구·층·랜드마크·연락 방식 상세 표시 | 경쟁사 인계 장소가 우리에게 허용됐다는 뜻은 아님 |
| Bounce의 QR 예약증·고객지원·보호 정보 | 기술 기능과 신뢰 정보를 함께 제공 | 보장 금액·정책을 복사하지 않음 |

따라서 차별화는 ‘최초의 짐배송’이 아니다. 중국어로 **내 호텔 이용 가능 여부→최종 가격→짐 맡기는 방법→공항 찾는 방법→현재 인계 상태**를 끊김 없이 처리하는 데 집중한다.

## 3. 기능 범위

| 기능 ID | 내용 | 단계 |
|---|---|---|
| CORE-01 | 한 브랜드 홈페이지·서비스 설명·FAQ·고객지원 | A |
| CORE-02 | zh-CN/ko/en, 라이트·다크·시스템 모드 | A |
| ADMIN-01 | 호텔·권역·슬롯·인계 장소·정책 관리 | A |
| BAG-01 | 호텔 검색·노선·짐 규격·항공편 입력 | B |
| BAG-02 | 서버 견적·수용량·비회원 주문·예약증 | B |
| PAY-01 | PG 결제·환불·대사 | B |
| OPS-01 | 호텔 보관·기사 배정·작업 | C |
| OPS-02 | 짐별 QR·사진·상태·수령 코드 | C |
| OPS-03 | 지연·분실·부분 인계·반환·문의 | C |
| PARTNER-01 | 호텔 QR·유입·수수료·정산 | D |
| BAG-03 | 공항→숙소, 숙소→숙소의 노선별 판매 | D |
| GROWTH-01 | 중국어 검색 페이지·콘텐츠·전환 측정 | D |
| WX-01 | 위챗 미니프로그램(web-view 하이브리드) | D |
| APP-01 | 현장용 PWA 설치·웹 푸시·오프라인 강화 (네이티브 앱 없음) | E |
| TRACK-01 | 검증된 차량 위치 연동 | E |

숙소→공항은 우선 완성할 사용자 여정이다. 데이터 구조는 세 가지 수하물 노선을 모두 표현할 수 있게 설계한다. 서비스 유형별 별도 장바구니·다른 물품 판매는 만들지 않는다.

고객 채널은 위챗·알리페이 내장 브라우저에서 동작하는 모바일 웹과 위챗 미니프로그램이다. 고객용 네이티브 앱은 범위에 없다. 근거는 [AGENTS.md 4절 앱 원칙](../AGENTS.md)이다.

## 4. 제품 가치와 신뢰 설계

예약 전에는 수거 마감·예상 배송 시각·공항 인계 기한을 보여준다. 결제 전에는 총액·취소 정책·금지 품목·보상 정책을 보여준다. 예약 후에는 수하물별 현재 상태와 마지막 업데이트 시각을 보여준다. 고객이 호텔 직원에게 보여줄 중국어·한국어 병기 카드를 제공한다.

신뢰 기능 우선순위는 QR·수량·사진·인계 기록 → 차량 최근 위치 → 개별 추적 장치 순이다. 저가 GPS 태그 가격만으로 실시간 추적 기능이 가능하다고 확정하지 않는다. 차량 위치와 짐 자체 위치를 UI에서 구분한다.

운영자가 설정해야 할 정보: 실제 승인된 공항 인계 위치, 호텔 지점·운영시간, 기사 연락 경로, 당일 마감, 짐 크기·금지 품목, 보험·보상 범위. 계약은 준비된 것으로 가정하지만 설정값이 없는 상태를 임의의 확정 약속으로 채우지 않는다.

## 5. 고객 검증을 돕는 제품 기능

제품에는 언어·노선·호텔·유입 경로별 견적 요청, 결제 확정, 취소, 정시 인계, 지원 문의 데이터를 기록한다. 현장 인터뷰나 설문은 개발의 선행 조건으로 두지 않는다. 운영자가 중국어 사용자 피드백을 주문과 분리해 등록·분류할 수 있게 한다.

핵심 지표:

- 견적→결제 확정 전환율: 유효 견적 세션 중 서버가 결제를 확인한 주문.
- 호텔별 주간 확정 주문과 실제 인계 완료 건수.
- 공항 ‘인계 준비 정시’와 ‘고객 실제 수령 정시’를 별도로 계산.
- 수하물별 증빙 완성률, 부분 인계 건수, 지원 문의율.
- 취소·환불 이유와 결제 실패 원인.

모든 비율에 표본 수·기간을 같이 표시한다. 고객 클릭 이벤트를 실제 배송 완료로 사용하지 않는다.

## 6. 수용 기준

- 중국어 첫 화면에서 예약 가능 호텔·날짜를 조회할 수 있다.
- 지원하지 않는 호텔·날짜에 결제 진입 불가.
- 고객이 수거 장소·시간·공항 수령 안내를 결제 전에 이해할 수 있다.
- 주문 1건에 짐 여러 개를 별개 상태로 추적한다.
- 고객·호텔·기사·운영자가 같은 주문의 자기 업무만 처리한다.
- 브랜드 사이트의 주 내비게이션이 수하물 서비스와 고객지원 중심이다.
