# 08. 중국인 고객 유입·호텔 제휴·전환 분석

연결: [메인](../AGENTS.md), [제품](01-product-brand-benchmark.md), [화면](02-information-architecture-journeys.md)

## 1. 기능 목표

중국인 관광객이 짐배송을 발견하고, 자기 호텔·날짜에 이용 가능한지 확인한 뒤 결제까지 완료하게 한다. 유입 채널은 호텔 프런트 QR, 중국어 검색 페이지, 샤오홍슈에서 연결한 상황별 콘텐츠, 기존 고객 공유 링크를 우선 지원한다. 다른 관광 상품을 판매하지 않는다.

공통 측정 흐름: 유입 → 호텔 조회 → 유효 견적 → 결제 확정 → 수거 → 약속한 시각의 인계 준비 → 고객 실제 수령. 광고 클릭 수나 화면 방문만으로 배송 성과를 계산하지 않는다.

## 2. 호텔별 QR·인쇄 안내

호텔 파트너 화면에서 자기 지점의 QR과 중국어 고객용·한국어 직원용 인쇄 자료를 생성한다. QR은 공개 랜딩 URL과 제휴 코드만 포함한다. 로그인 비밀값, 고객 주문 토큰, 정산 정보는 포함하지 않는다.

호텔 랜딩은 해당 지점을 미리 선택하고 판매 중인 노선·수거 마감·프런트 인계 방법을 보여준다. 같은 이름의 다른 호텔 지점은 주소·사진으로 구분한다. 인쇄 자료에 정책·인계 장소 버전과 최종 갱신일을 표시한다. 공항 수령 위치가 바뀌면 랜딩은 최신 승인 위치를 보여주고 기존 예약 고객에게 변경 알림 작업을 만든다.

제휴 코드에는 활성 호텔·유효 기간·적용 노선·할인 중복 규칙을 저장한다. 주문 생성 때 서버가 제휴 귀속을 확정한다. 결제 후 URL을 바꿔 수수료 수취인을 변경할 수 없다. 호텔 직원은 자기 지점의 유입·완료 실적만 조회한다.

## 3. 중국어 검색·콘텐츠

중국어 간체를 기본으로 출국일 체크아웃, 제주 도착 직후, 호텔 이동일의 세 가지 상황을 설명하는 페이지를 만든다. 페이지는 실제 판매 가능한 호텔·노선·마감·예약 행동으로 연결한다. 검색어만 반복한 유사 페이지를 대량 생성하지 않는다.

| 콘텐츠 | 답할 질문 | 연결 노선 |
|---|---|---|
| 출국일 체크아웃 | 짐을 맡기고 공항에서 언제 찾나? | 숙소→공항 |
| 도착 직후 관광 | 체크인 전 짐을 숙소로 보낼 수 있나? | 공항→숙소 |
| 호텔 이동 | 다른 숙소로 짐을 옮길 수 있나? | 숙소→숙소 |
| 공항 수령 안내 | 층·출구·랜드마크·수령 코드는? | 모든 관련 주문 |
| 요금·보상 FAQ | 총액·취소·지연·분실은 어떻게 되나? | 견적·지원 |

콘텐츠 필드: locale, 제목, 요약, 본문, 이미지 대체 텍스트, 관련 노선·호텔, 작성·검수자, 상태, 사실 확인일, 근거 URL. 공항 장소·가격·보상 조건은 콘텐츠마다 복사하기보다 운영 설정을 참조한다. 필수 취소·보상 문구는 중국어 검수본을 게시해야 해당 언어로 판매 가능하다.

## 4. 샤오홍슈 콘텐츠 기록

운영 화면에는 소재명·게시 URL·날짜·키워드·랜딩 페이지·캠페인 코드·담당자·유입·예약 결과를 기록한다. 주제는 ‘체크아웃 후 관광’, ‘호텔 이동’, ‘공항에서 내 짐 찾기’처럼 실제 사용 상황 중심이다.

샤오홍슈 자동 게시·DM 발송·게시물 수집은 공식 지원과 정책을 확인한 경우에만 별도 연동한다. 녹취에서 언급한 게시물 수를 검증된 시장 수치로 표시하지 않는다. 캠페인 효과는 조회수뿐 아니라 유효 견적·결제 확정까지 연결한다. 유입 속성이 누락된 주문은 ‘알 수 없음’으로 유지한다.

## 5. 분석 이벤트와 대시보드

| 이벤트 | 서버·클라이언트 기준 | 속성 |
|---|---|---|
| `landing_viewed` | 공개 페이지 유효 조회 | locale, route, channel |
| `hotel_selected` | 지점 선택 | hotel_id, direction |
| `quote_created` | 서버 견적 성공 | 분석용 quote 참조, route_type |
| `order_held` | 서버 주문·홀드 생성 | 날짜, channel |
| `payment_confirmed` | PG 서버 검증 성공 | 금액, 통화, 수단 |
| `bag_collected` | 기사 수거 확정 | 비식별 route 참조 |
| `handoff_ready` | 약속 장소에서 실제 수령 가능 | 정시 여부 |
| `bag_delivered` | 수령 코드 검증 | 짐 개수, 실제 인계 시각 |
| `support_created` | 문의 저장 | 유형, 노선 |

결제·짐 인계는 서버 이벤트로 집계한다. 이메일·전화·이름·사진 URL·정밀 위치·수령 코드를 분석 데이터에 넣지 않는다. 비필수 마케팅 분석은 동의를 반영한다. 분석 스크립트가 막혀도 거래·인계 기록은 유지된다.

대시보드는 언어·노선·호텔·캠페인별 견적·결제·취소·환불·수거·정시 준비·실제 수령 건수를 보여준다. 비율에는 분모·기간을 함께 표시한다. 호텔 QR 유입과 호텔이 실제 인계한 건수를 구분한다.

## 6. 개선 실험

랜딩 문구·예약 버튼·호텔 카드·안내 사진을 버전으로 관리한다. 고객이 본 버전을 세션/주문에 기록하고 미리 정한 결과 지표로 비교한다. 가격·취소·보상 조건을 변경하면 정책 버전과 고객 고지를 보존한다.

주문 규모가 작은 기간에는 비율만으로 확정적 성과를 말하지 않고 실제 건수를 제시한다. 호텔별 반복 사용을 위해 프런트 문의·QR 배치·인쇄 자료 버전·예약 오류·취소 사유를 운영자가 볼 수 있게 한다.

## 7. 중국 접속 품질

중국 본토망, 중국 유심 로밍, 제주 현지 Wi-Fi에서 같은 호텔 조회→사진→결제→복귀→주문 재조회 흐름을 테스트한다. 도메인·페이지 크기·폰트·외부 스크립트별 실패를 기록한다. 첫 화면조차 열리지 않는 접속 실패와 페이지를 보고 예약하지 않은 전환 실패를 별도로 분류한다.

## 8. 수용 기준

- 호텔 QR에서 해당 지점이 선택된 중국어 예약 화면으로 이동.
- 결제 후 제휴 코드 수정으로 정산 귀속 변경 불가.
- 미승인 중국어 필수 정책으로 결제 진입 불가.
- 분석 차단 상태에서도 결제·배송 서버 이벤트가 기록됨.
- 대시보드 비율에 분모·기간 표시.
- 분석 데이터에 연락처·주문 접근 토큰·사진 URL 없음.
- 중국망 품질을 실제 테스트하지 않았다면 ‘미검증’ 표시.
