# 10. 첨부 시안 기반 모바일 UI 디자인 명세

## 1. 시안에서 가져올 방향

하나의 브랜드 **제주 커넥트** 안에서 수하물 예약, 예약증, 배송 조회, 고객지원을 이어 주는 모바일 중심 UI를 만든다. 브랜드명은 개발용 표시명이며 설정에서 교체 가능하다. 제주 바다의 청록색, 밝은 하늘, 현무암 해안, 주황색 캐리어를 시각적 단서로 사용한다. 화면의 첫 문장은 ‘짐을 맡기면 남은 제주 여행이 편해진다’는 가치를 전하고, 바로 아래에서 호텔·날짜를 입력할 수 있게 한다.

첨부 이미지는 **시각적 레퍼런스**다. 이미지의 `JC-DEMO-0930`, `₩30,000`, `11:00`, `16:00–18:00`, 지도 경로, 채팅 내용은 예시이며 실제 요금·영업시간·수령 장소·운송 위치를 뜻하지 않는다. 글자가 섞여 있거나 부정확한 부분은 그대로 베끼지 않고 승인된 중국어 문구와 운영 데이터로 교체한다. QR은 이미지에서 잘라 쓰지 않고 서버가 발행한 식별자로 생성한다.

## 2. 화면 구조와 탐색

| 시안 | 구현 화면 | 첫 화면에서 보여줄 핵심 | 주 행동 |
|---|---|---|---|
| 01 메인 | `/{locale}` | 가치 제안, 노선 3개, 호텔·날짜, 인계 마감 안내 | 이용 가능 시간 조회 |
| 02 배송 예약 | `/{locale}/luggage/book` | 노선→짐→확인의 단계, 짐 수량, 수거·수령 창, 서버 견적 | 확인하고 결제 |
| 03 예약증·QR | `/{locale}/orders/{orderId}`의 예약증 영역 | 서버 확정 상태, 주문 ID, 출발·도착, 짐별 태그·인계 안내 | 예약증 보기·저장 |
| 04 배송 조회 | 같은 주문 화면의 배송 영역 | 짐별 현재 상태, 마지막 확인 시각, 수령 장소와 예정 창 | 수령 안내 보기·지원 연결 |
| 05 고객지원 | `/{locale}/help` 및 주문 문의 | 주문 맥락, FAQ, 문의 채널, 상담 내역 | 문의 접수·진행 확인 |

모바일 고객 하단 탭은 **홈 / 예약 / 내 주문 / 고객지원** 네 가지로 한다. 시안의 ‘我的’는 계정·설정 진입점으로 헤더 또는 내 주문 화면에 배치한다. 로그인한 기사·호텔·운영자에게는 별도 업무 내비게이션을 제공한다. 현재 범위는 중국인 대상 수하물 플랫폼이므로 관광 티켓, AI 스튜디오, 출판, 일반 관광 챗봇을 고객 메뉴에 넣지 않는다. 실시간 번역·도슨트는 훗날 추가할 수 있는 독립 메뉴 슬롯만 고려하며 현재 제공 기능처럼 표시하지 않는다.

## 3. 시각 토큰

[03 디자인 문서](03-design-i18n-theme-accessibility.md)의 의미 토큰을 사용한다. 아래는 첨부 시안에 맞춘 **시각 목표값**이며 실제 텍스트 대비와 다크모드 검증 후 조정한다.

| 역할 | 라이트 목표 | 다크 목표 | 사용 규칙 |
|---|---|---|---|
| 브랜드 청록 | `#0F766E` | `#5EEAD4` | 로고·링크·선택 표시 |
| 주요 행동 | `#0F766E` | `#5EEAD4` | 한 화면의 가장 중요한 버튼 1개 |
| 해양 배경 | `#E7F7F9` | `#11333B` | 안내 카드·지도 주변 보조 배경 |
| 기본 배경 | `#F8FAFC` | `#0B1220` | 페이지 |
| 카드 | `#FFFFFF` | `#111C2E` | 예약·짐·문의 카드 |
| 주 텍스트 | `#0F172A` | `#F1F5F9` | 본문·가격·시각 |
| 보조 텍스트 | `#475569` | `#CBD5E1` | 설명·마지막 갱신 |
| 따뜻한 강조 | `#C84B00` | `#FDBA74` | 마감·주의·가격의 제한적 강조 |
| 선·입력 경계 | `#CBD5E1` | `#475569` | 구분선·폼 경계 |

시안의 부드러운 카드와 여백을 살리되, 금융·인계 정보는 사진 위나 흐린 그라디언트 위에 올리지 않는다. 기본 카드 모서리 16px, 주 버튼 12px, 카드 간격 12–16px, 페이지 좌우 여백 16px을 시작값으로 둔다. 모바일 본문은 16px, 주요 제목 24–28px, 가격·인계 시각은 18–22px로 시작한다. 터치 영역은 44×44 CSS px 이상이다. 그림자보다 테두리와 배경 차이를 우선해 다크모드에서도 카드 경계를 유지한다.

## 4. 화면별 구현 지침

### 01 홈: 제주 이미지 + 즉시 조회

- 상단에 로고, `简体中文 / 한국어 / English` 전환, 라이트·다크 토글을 둔다. 작은 기기에서는 설정 버튼으로 묶되 예약 CTA보다 눈에 띄지 않게 한다.
- 히어로는 제주 바다·현무암·캐리어가 함께 보이는 이미지를 사용한다. 이미지 속 문구는 모두 HTML 텍스트로 분리해 번역·확대·스크린리더를 지원한다. 사용 권리가 확인된 사진 또는 자체 제작 자산만 쓴다.
- 노선 선택은 **호텔→공항 / 공항→호텔 / 호텔→호텔** 세 개. 판매가 닫힌 노선은 숨기거나 비활성 사유를 보여 주며 예약 가능한 것처럼 만들지 않는다.
- 접힌 검색 카드에는 출발 호텔, 날짜, 선택 노선을 둔다. 호텔 선택 결과는 같은 이름의 지점을 주소·권역으로 구별한다. 조회 전에는 예시 요금을 확정가처럼 보여 주지 않는다.
- 하단 ‘내 짐’ 요약은 주문 소유권이 확인된 고객에게만 나타난다. 비회원 복구는 [02 문서](02-information-architecture-journeys.md)의 검증 흐름을 따른다.

### 02 예약: 단계와 금액을 항상 이해할 수 있게

- 상단 단계 표시는 `路线 → 行李 → 确认`처럼 **현재 단계와 총 단계**를 텍스트로도 제공한다. 시안의 2단계 화면은 짐 선택의 목표 형태다.
- 출발·도착 카드에는 호텔/공항의 정확한 지점명, 한국 시간 기준 날짜, 수거 마감, 예상 수령 창을 함께 표시한다. 항공편 정보가 필요하면 별도 입력한다.
- 짐 수량 스테퍼는 최소·최대와 규격을 서버 설정에서 가져온다. 수량 변경은 서버 견적을 다시 받아 합계를 갱신한다. 로딩 중 과거 가격을 확정가처럼 두지 않는다.
- 화면 하단 고정 요약은 **총액 + 통화 + 다음 행동**만 담고, 키보드·safe area를 가리지 않는다. 상세 요금·취소 조건·금지 품목은 결제 전에 펼쳐 볼 수 있어야 한다.
- ‘호텔 프런트에 맡기세요’ 같은 문장은 해당 지점의 실제 인계 방식과 맞을 때만 표시한다.

### 03 예약증: 인계용 QR과 주문 상태를 분리

- 결제창 복귀 직후에는 `결제 확인 중`일 수 있다. 서버 검증 전에는 초록 체크와 `예약 성공 / 已支付`를 표시하지 않는다.
- 확정 후 주문번호, 노선, 날짜, 짐 수량, 인계 마감, 직원에게 보여 줄 한국어 문구를 표시한다.
- QR은 **태그 식별/인계 용도**와 **고객 수령 확인**을 구분한다. 개인정보나 주문 전체 열람 권한을 QR에 담지 않는다. 수령 코드는 별도의 만료·시도 제한을 따른다.
- 짐별 상태를 각각 보여 주어 부분 수거·부분 수령을 표현한다. `예약증 저장`은 오프라인 사본임을 알리고 마지막 서버 확인 시각을 함께 남긴다.
- QR은 밝은 단색 배경과 충분한 여백을 유지하며 실제 기기·인쇄 판독을 검사한다.

### 04 배송 조회: 상태가 우선, 지도는 보조

- 최상단 상태 카드에는 `운송 중 / 运输中`처럼 **텍스트·아이콘·색**을 함께 쓰고, 다음 예정 행동과 마지막 확인 시각을 적는다.
- 기본 타임라인은 `호텔 인수 → 기사 수거 → 운송 중 → 공항 인계 준비 → 고객 수령`이다. 각 단계는 **확정된 이벤트**에서만 완료 표시한다. `공항 인계 준비`와 `고객 수령 완료`는 다른 상태다.
- 지도는 위치 데이터가 있을 때만 보여 준다. 초기 QR·인계 이벤트만 있는 단계에서는 제주 그림 지도에 움직이는 차량이나 점선 경로를 그려 실시간 추적처럼 보이게 하지 않는다. 차량 위치가 제공되면 ‘배송 차량의 최근 위치’와 관측 시각·갱신 지연을 명시한다. 개별 GPS 장치가 검증되기 전에는 ‘내 캐리어의 실시간 GPS’라고 쓰지 않는다.
- 공항 수령 카드에는 관리자가 승인한 층, 출구, 랜드마크, 사진, 운영시간, 한국어·중국어 안내를 표시한다. 장소 변경은 최신 버전으로 교체하고 이전 안내와 혼동되지 않게 한다.
- 지연·사고 상태는 예상 도착을 임의로 약속하지 않고 확인된 새 시간과 지원 연결을 보여 준다.

### 05 고객지원: 실제 접수 가능한 채널만

- 첫 카드에 **내 주문 상태, 수령 위치, 지연·짐 이상, 예약 변경** 바로가기를 둔다. 로그인/guest 소유 확인이 없으면 다른 주문 내용을 미리 보여 주지 않는다.
- 실시간 상담 UI는 실제 상담 채널·운영시간·전송/수신 상태가 구현된 경우에만 켠다. 아직 채팅 백엔드가 없으면 작동하지 않는 입력창 대신 문의 접수 폼과 회신 방법을 제공한다.
- 상담 기록에서 고객 메시지와 운영자 답변을 분리하고, 주문번호·현재 상태는 권한이 확인된 문의에만 연결한다.
- 실시간 번역이나 도슨트 챗봇을 후속 확장할 때도 **상담 응답인지 자동 번역/AI 답변인지** 명확히 표시한다. 현재 수하물 문제 해결 경로를 대체하지 않는다.

## 5. 반응형·앱 확장

- 360–430px 모바일을 우선 설계하고, 320px 및 200% 확대에서도 핵심 정보와 CTA가 잘리지 않게 한다. 모바일 하단 탭은 safe-area를 포함한다.
- 태블릿에서는 홈 히어로와 검색 카드를 나란히 둘 수 있다. 데스크톱에서는 고객 예약 폼과 요약을 2열로 구성하되 카드 읽기 순서와 키보드 순서는 유지한다.
- PWA·위챗 미니프로그램 web-view에서도 같은 정보 구조를 사용하지만 상태바·노치·키보드·공유/저장 동작은 플랫폼별로 검증한다. 앱스토어용 화면을 웹 스크린샷 그대로 고정하지 않는다.
- 네트워크가 끊기면 저장된 예약증의 마지막 확인 시각을 표시한다. 새 결제·최종 인계는 연결 복구 전 성공 상태로 바꾸지 않는다.

## 6. 필수 상태와 문구

모든 화면에 `loading / empty / ready / partial / error / offline` 상태를 설계한다. 예약 화면에는 추가로 `견적 만료 / 슬롯 마감 / 결제 검증 중`, 배송 화면에는 `부분 수거 / 부분 인계 / 위치 갱신 지연 / 사고`, 지원 화면에는 `운영시간 외 / 전송 실패`를 둔다. 상태 변화는 색만으로 전하지 않는다.

대표 중국어 간체 문구는 디자인 검토용 초안이며 게시 전 언어 검수를 거친다.

| 목적 | zh-CN 초안 | ko |
|---|---|---|
| 히어로 | 把行李交给我们，轻松游济州 | 짐을 맡기고 가볍게 제주를 여행하세요 |
| 조회 | 查询可预约时段 | 예약 가능한 시간 조회 |
| 호텔 인계 마감 | 请在韩国时间 {time} 前交给酒店前台 | 한국 시간 {time} 전까지 호텔 프런트에 맡겨주세요 |
| 결제 검증 | 正在确认付款，请勿重复支付 | 결제를 확인 중입니다. 중복 결제하지 마세요 |
| 운송 중 | 行李运输中 · 更新于 {time} | 짐 운송 중 · {time} 갱신 |
| 공항 수령 | 查看机场领取地点 | 공항 수령 장소 보기 |
| 위치 출처 | 配送车辆最近位置，并非行李本身的 GPS | 배송 차량의 최근 위치이며 짐 자체의 GPS는 아닙니다 |

## 7. 구현·검수 체크

1. 첨부 시안의 5개 화면을 디자인 레퍼런스로 연결하되 실제 컴포넌트는 라이브 데이터·운영 설정을 받는다.
2. `zh-CN / ko / en` 각각에서 제목·탭·버튼·날짜·금액·장소명이 잘리지 않는다. 이미지만 번역해 바꾸지 않는다.
3. 라이트·다크 전환 후 텍스트, 버튼, 경고, 포커스, QR 대비를 확인한다.
4. 가격·마감·위치·QR·결제 성공·상담 가능 여부에 가짜 확정 데이터가 표시되지 않는다.
5. 주문 2개 이상, 짐 3개 중 일부 인계, 마감 직전, 위치 정보 없음, 네트워크 단절 화면을 검수한다.
6. 고객용 중국어 화면과 직원용 한국어 인계 카드가 **같은 주문·같은 지점 ID**를 가리킨다.
