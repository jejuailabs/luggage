# 02. 중국어 예약·호텔·기사·운영자 화면

연결: [메인](../AGENTS.md), [제품](01-product-brand-benchmark.md), [권한](05-data-auth-security.md)

## 1. 공개 URL과 메뉴

공개 URL에는 `/{locale}`를 사용한다. `zh-CN`이 고객 기본값이며 `ko`, `en`을 지원한다. API는 locale 경로를 쓰지 않는다.

| URL | 화면 | 접근 |
|---|---|---|
| `/{locale}` | 제주 짐배송 홈, 서비스 설명, 예약 시작 | 공개 |
| `/{locale}/luggage` | 세 가지 노선, 짐 규격·금지 품목·보상 | 공개 |
| `/{locale}/luggage/book` | 호텔·날짜·짐·항공편·견적·연락 | 공개/보호된 guest 세션 |
| `/{locale}/checkout/{orderId}` | 예약 결제 | 주문 소유자 |
| `/{locale}/orders/{orderId}` | 예약증·짐별 상태·공항 수령 안내 | 주문 소유자 |
| `/{locale}/hotels/{slug}` | 해당 호텔 인계 설명·예약 | 공개 |
| `/{locale}/guide/{slug}` | 짐배송 이용·공항 인계·체크아웃 안내 | 공개 |
| `/{locale}/help` | FAQ·문의 | 공개 |
| `/{locale}/help/requests/{id}` | 문의 내역 | 소유자·담당 직원 |
| `/{locale}/account` | 내 주문·언어·테마·계정 삭제 | 본인 |
| `/{locale}/driver` | 기사 작업·QR·인계 | 배정 기사 |
| `/{locale}/partner` | 호텔 보관·기사 인계 | 해당 호텔 직원 |
| `/{locale}/admin` | 배차·주문·호텔·정산·지원 | 담당 업무 권한 |
| `/{locale}/legal/{slug}` | 약관·개인정보·취소·보상 | 공개 |

고객 모바일 메뉴는 홈 / 짐배송 예약 / 내 예약 / 도움말이다. 호텔·기사·운영자는 로그인 후 자기 업무 화면으로 진입한다. 일반 고객에게 업무 메뉴를 숨기고 직접 URL도 권한 검사로 차단한다.

## 2. 고객 홈과 예약 시작

첫 화면은 ‘출국일 짐 없이 관광’ 사용 상황과 날짜·출발 호텔 조회를 우선 보여준다. ‘공항에서 숙소로’, ‘숙소에서 숙소로’는 같은 서비스의 다른 노선 선택으로 제공한다. 예약 가능한지 아직 모르면 가격을 확정적으로 표시하지 않는다.

홈에서 바로 확인할 정보: 이용 가능한 호텔, 짐 맡길 시각, 공항에서 찾을 장소·시각, 이용 요금, 배송 상태 확인 방식, 문제가 생길 때 연락 방법. 후기·제휴 호텔 로고는 실제 승인된 데이터만 노출한다.

## 3. 예약 여정

| 단계 | 고객 입력 | 서버가 확인할 것 | 성공 화면 |
|---|---|---|---|
| 노선 | 출발·도착 호텔/공항, 날짜 | 호텔 지점·권역·방향 판매 여부 | 가능한 슬롯 |
| 시간 | 수거·수령 희망 시간, 항공편 | 컷오프·비행기 안전 여유·용량 | 정확한 한국 시간 안내 |
| 짐 | 개수·크기·선택 사진 | 규격·수량·금지 품목 | 짐별 요약 |
| 견적 | 쿠폰·호텔 제휴 코드 | 서버 요금·유효시간 | 총액·취소 조건 |
| 연락 | 이름·지원 연락수단·필수 동의 | 형식·정책 버전 | 최종 요약 |
| 결제 | 가능한 PG 수단 선택 | 홀드·주문 소유권·결제 검증 | 확인 중→예약 확정 |
| 예약증 | QR·병기 안내 카드 열기 | 서버 확정 상태 | 호텔 제시·공항 수령 안내 |

한국 전화번호를 필수로 요구하지 않는다. 지원하는 국제 전화·이메일·위챗 채널 중 실제 검증 가능한 방법을 선택한다. 연락처 문자열만으로 주문 소유권이 확인된 것은 아니다. 항공편 API 미연동이면 항공편명·출발시각을 직접 입력하게 한다.

사진을 결제 전에 필수로 받는지, 결제 후 일정 시각까지 등록하는지는 운영 설정이다. 업로드 실패가 결제된 주문을 삭제하지 않는다. 사진이 필요한 상태는 ‘추가 정보 필요’로 표시한다.

## 4. 비회원 주문 복구

현재 기기에서는 보호된 guest 세션으로 주문 재조회가 가능하다. 다른 기기는 검증된 연락 채널로 받은 단기 코드 또는 복구 링크를 교환해 접근한다. 주문번호+이름만 입력하면 상세 페이지가 열리는 구조를 만들지 않는다.

회원 전환 시 원 guest 세션 또는 별도 소유 검증을 확인한 후 주문을 연결한다. 같은 이메일 주소만으로 병합하지 않는다. QR 예약증은 인계용 식별자이며 주문 전체 읽기 권한을 부여하지 않는다.

## 5. 주문·배송 화면

- 상단: 지금 고객이 해야 할 행동과 한국 시간 기준 마감.
- 예약 정보: 출발·도착 지점, 수거·수령 창, 항공편, 짐 개수.
- 짐별 타임라인: 호텔 보관→기사 수거→이동→공항 준비→고객 수령.
- 증빙: 본인 짐의 수거·인계 사진과 시각.
- 호텔 카드: 중국어 안내와 호텔 직원에게 보여줄 한국어 문구.
- 공항 카드: 실제 승인된 층·출구·랜드마크·사진·연락 경로.
- 추적: 마지막 업데이트 시각, 차량 최근 위치가 있는 경우 그 출처 표시.
- 지연/사고: 변경된 예상 시각, 담당 지원 연결, 처리 상태.

‘공항에서 수령 가능’과 ‘고객이 실제 수령함’을 분리한다. 세 개 중 두 개만 인계되면 ‘2/3개 수령’으로 표시한다. 고객에게 다른 주문의 사진·위치·짐을 노출하지 않는다.

## 6. 호텔·기사·운영자 여정

호텔: 오늘 예약 확인 → 고객이 맡긴 짐 수량 대조 → 태그 부착·보관 위치 → 보관 확정 → 배정 기사 확인 → QR·수량 대조 → 기사 인계. 호텔은 자기 지점 주문만 본다.

기사: 배정 노선 조회 → 수거 지점 이동 → QR·외관 확인 → 사진·수량 기록 → 적재 목록 점검 → 목적지 이동 → 수령 코드·짐 대조 → 인계 또는 예외 기록. 재배차되면 이전 기사의 수정 권한을 종료한다.

운영자: 미확정·미수거·지연·공항 대기·부분 인계·사고를 우선 확인 → 배차 조정 → 고객·호텔·기사 연락 → 대안 인계/반환/환불 처리. 정산 담당과 고객지원 담당의 권한을 분리한다.

## 7. 공통 오류·빈 상태

| 상황 | 고객·직원에게 보일 정보 | 가능한 행동 |
|---|---|---|
| 해당 호텔 미지원 | 현재 판매 범위 밖 | 다른 지점·문의 |
| 슬롯 마감 | 방금 선택한 시간대가 마감됨 | 다른 시간·날짜 |
| 견적 만료 | 최신 금액 확인 필요 | 입력 유지한 채 재견적 |
| 결제 결과 지연 | 확인 중, 중복 결제 주의 | 서버 상태 조회·지원 |
| 사진 실패 | 주문 유지, 사진 미등록 | 압축·재시도·기사 보완 |
| 네트워크 단절 | 저장된 예약증의 마지막 확인 시각 | 연결 후 최신 상태 확인 |
| 고객 미도착 | 수령 대기 기한·보관 안내 | 지원 연결 |
| 권한 없음 | 접근할 수 없는 주문 | 본인 계정·복구 |

모든 주요 화면은 loading/empty/ready/partial/error/offline 상태를 정의한다. 다른 언어로 바꿔도 입력·주문 ID를 유지한다. 결제 복귀나 새로 고침 후 브라우저 화면보다 서버 주문 상태를 우선한다.

## 8. 수용 기준

- 360px 모바일 폭에서 주요 예약 화면의 가로 넘침이 없다.
- 결제 이전에 총액·시간·수령 장소·취소 조건이 보인다.
- zh-CN/ko/en 전환 중 입력값을 잃지 않는다.
- 호텔·기사·운영자가 배정되지 않은 주문 URL에 접근할 수 없다.
- 공항 인계 장소 변경 시 고객에게 최신 안내가 보인다.
- 고객은 중국어 카드, 현장 직원은 한국어 카드로 같은 주문을 식별한다.
